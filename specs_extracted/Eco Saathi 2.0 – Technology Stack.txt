Eco Saathi 2.0 – Technology Stack
☐ Version 1.0 · Draft · 15 October 2026 · Companion to the PRD
1. Purpose and Approach
This document recommends the technologies for rebuilding ecosaathi.com. The choices follow four principles:
Fit for a small team: managed services over self-hosted ones wherever possible.
India-ready: UPI, local payment gateways, local shipping partners, GST invoices and a Mumbai cloud region.
Fast on mobile: server-rendered pages, image optimisation and a CDN.
Replaceable parts: each integration (payments, email, WhatsApp, AI) sits behind an adapter, so a provider can be swapped without a rewrite.
The tools below are recommendations. Final selection depends on the platform decision in section 3 and on budget.

3. Key Decision: Platform
The current store runs on Typof, a hosted store builder. Before development starts, the team should confirm whether it allows custom scripts, webhooks, API access and a custom chat widget.
Option
Best when
Trade-offs
A. Stay on the current platform and customise
Budget and time are very limited and it supports the needed integrations
Limited control; chatbot and WhatsApp flows may be restricted
B. Headless build with Medusa and Next.js (recommended)
The business wants full control and a custom experience
Needs developer time and hosting management
C. Shopify with a custom theme or headless storefront
The team prefers a managed commerce platform
Monthly fees and app costs; less backend flexibility
D. WooCommerce on WordPress
The team is already comfortable with WordPress
Plugin sprawl, more security patching, slower without tuning
Recommendation: Option B for the full Eco Saathi 2.0 scope. Option C is the safer managed alternative if the team cannot maintain servers.
4. Frontend Details
Rendering: static generation for content pages and category pages, server rendering for product and search pages, incremental regeneration when products change.
Performance: image optimisation (WebP or AVIF), lazy loading, font subsetting, code splitting, and a target mobile Largest Contentful Paint under 2.5 seconds.
SEO: metadata per page, JSON-LD structured data for products and breadcrumbs, XML sitemap, canonical URLs and 301 redirects from existing URLs.
Progressive Web App: installable on phones, with an offline fallback page.
Accessibility: semantic HTML, alt text, colour-contrast checks, keyboard navigation.
Languages: English at launch, with the codebase prepared for Odia and Hindi through an i18n library.
5. Backend Details
Pattern: a modular monolith first (commerce engine plus a custom services layer), split into services only when scale demands it.
API style: REST for the storefront, webhooks for payment, shipping and WhatsApp events.
Background jobs: queue workers for emails, WhatsApp messages, stock sync, abandoned-cart reminders and invoice generation.
Invoices: GST-compliant PDF invoices generated on order completion.
Admin: the commerce engine's admin panel, extended with a chatbot conversation viewer and a corporate leads view.

9. Testing Strategy
Unit tests for pricing, discounts, tax and stock logic.
Integration tests for checkout, payment webhooks and shipping webhooks.
End-to-end tests (Playwright) for the main purchase journey on mobile and desktop.
Chatbot evaluation set, run on every prompt or model change.
Load test before festival campaigns.
Lighthouse checks in CI for performance, accessibility and SEO.
10. Indicative Running Costs
Costs depend on traffic and vendor pricing, which changes often, so these are categories rather than figures. Verify current prices before budgeting.
Fixed: hosting, managed database, search, monitoring, domain.
Per order: payment gateway fee, shipping charges, WhatsApp conversation fees, SMS or OTP fees.
Usage-based: email sending and AI model usage (controlled through rate limits and caching of common answers).
